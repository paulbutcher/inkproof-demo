# Inkproof.Demo design

## Theorem index and trusted computing base

`Inkproof.Demo.TheoremIndex`, `Tcb` and `Page` are native modules that do not import Lasm. `lake exe theorem-index <project dir> <output.html>` reads each pinned library's `API.lock` and sources from `<project dir>/.lake/packages`, so the page always describes the releases the demo is built against. A theorem links to its declaration at the library's tag, or to the module its namespaces name when it has no declaration of its own (a structure field, an instance). Line counts of generator templates, generated output and hand-written JavaScript shims are measured from the same sources.

## Decimation toggle and pixel inspector

`Inkproof.Demo.Inspect` is a native module that does not import Lasm. `Decimation` selects between the library's guaranteed reduction (`reducePoints`) and naive decimation, which keeps the first sample of each pixel column and drops the rest; the toggle is `Decimation.toggle`. `inspect` gives, for one pixel column, the raw samples, their lowest and highest values computed by a plain fold that shares nothing with the library's reduction, and the extremes of what the guaranteed reduction draws, so the two can be compared. The plain-English statement of `Inkproof.Scene.reducePoints_covers` is shown beside its formal statement, read from the pinned release's `API.lock`. That the drawn extremes equal the raw ones is tested over generated series rather than proved: it needs `reduceRun_spec` lifted through `groupByKey`.

## Browser app

`app/` is the Lasm browser build: `App.lean` is a Lasm.UI app over the native modules, drawing the series (`Inkproof.Demo.Series`) as an SVG polyline under the chosen `Decimation`, with the toggle and the inspector panel (`Reading.html`) beside it. The root `package.json` (Lasm resolves JavaScript bindings from the Lake project's root) takes the Gpu interpreter and the custom-element shim from the pinned `inkproof-web` package under `.lake/packages`, so `lake build` must run before `npm ci`. `lake test` installs the npm packages, builds it with Vite and runs `app/browser.test.mjs` in headless Chromium. Tests check that naive decimation draws fewer points and a higher lowest peak than the guaranteed mode, that toggling back restores the same points, and that the inspector shows the raw sample count, the maximum and the guarantee.

## Drawing

`Inkproof.Demo.Draw` is a native module that does not import Lasm. `bytes` is the wire encoding of Gpu's `frame` (setup, then `compile` over one tile whose grid is device pixels from the top left, with Gpu's `tessellate` for the vertex words) on a white target, the `commands` of a Web `Scene`. Tested that every quake marker is one draw.

`Inkproof.Demo.Plot` is a native module that does not import Lasm. `traces` gives each station's per-column extents to Scene's `compileEnvelope`, one envelope per station in its own track with a gap wherever a column is absent so an outage is never bridged, and `quakes` turns the quakes in view into markers. `src` and `parseSrc` carry the visible sample range through a chart element's `src` attribute.

## Seismic model

`Inkproof.Demo.Seismic` is a native module that does not import Lasm. A `Station` is a pseudo-random trace that is absent during its outages; samples become `Extent` (minimum and maximum) leaves of a Core `Pyramid`, so a tile node is the extent of the samples under it and a range with no samples is a gap (`isGap`). The earthquake catalogue is a Core `Series` drawn with Scene's `compileScatter`, which gives every catalogued quake a marker whatever the view. The theorems that need Core's proof modules (`isGap_fold`, `marker_of_quake`) live in `test/Main.lean`, so the browser build does not link them. `Inkproof.Demo.Stack` turns a station's pyramid and a view into pixel-column extents (`span`; a column wholly inside an outage is absent), which `Plot.traces` draws with Scene's `compileEnvelope`. `Inkproof.Demo.View` turns Viewport's interval, which does the zooming and panning, into the visible sample `Range` clamped to the recording by Viewport's `Interval.indexRange`, and `Plot.bins` puts each quake in view in a pixel column through Core's `Binning`. The browser app draws four stations stacked, with a marker for each quake in view, and buttons to zoom and pan.

## Tiles

`Inkproof.Demo.Tiles` is a native module that does not import Lasm. Each level of a station's pyramid is cut by Core's `Pyramid.tile` into files of `tileSize` nodes, `s<station>/l<level>/t<n>.bin`, and a node is two little-endian 16-bit words, lowest then highest, with the gap word twice for a node with no samples (`decodeNode_encodeNode`, `decodeNode_gap`). `lake exe build-tiles <dir>` writes the files and a `manifest.json` of level sizes; `lake test` writes them to `app/web/public/tiles` before the Vite build, so the static site carries them. The stations are listed in `gen/BuildTilesMain.lean` and again in `app/App.lean`.

`Inkproof.Demo.Place` puts the samples of each miniSEED record on a grid of `rate` samples per second from the start of a day (`place`, of size `place_size`); a stretch no record covers stays `none`, so an outage becomes a gap. `gen/BuildRealTilesMain.lean` reads a station's day files, scales counts into 16 bits if they exceed it, and writes the same tiles as above. It is the executable `build-real-tiles`. It makes two passes over the day files, the first for the largest count (to scale into 16 bits), the second cutting the samples into chunks of 2^20, building each chunk's pyramid and writing its tiles up to level 12, so memory is bounded by a chunk and not the recording; the level-12 nodes of all chunks are then the leaves of one more pyramid that gives the levels above. Tiles are written only from level 4 up (nodes of 16 samples or more, `firstLevel` in the manifest); the samples themselves are written one file per recorded day, `s0/raw/d<day>.bin`, as 16-bit words with the gap word for a missing sample (`rawBytes_size`), for the finest zooms to read by byte range; a day with no file is a gap. The tiles are byte for byte those of one pyramid over all the samples, checked on two days with a day between them (a day with no file is a gap).

`Inkproof.Demo.TileRead` is a native module that does not import Lasm: what the browser loader asks of the tile files for a view. `levelFor` picks the widest level whose nodes fit a pixel column (`pow_levelFor_le`, `lt_pow_levelFor`), `nodeRange` and `tileRange` give the nodes and then the tile files overlapping a sample range (`nodeRange_covers`, `tileRange_covers`), and `decodeTile` reads a fetched file back into nodes (`length_decodeTile`).

## Performance test

`app/browser.test.mjs` loads the page under a 4x CPU slowdown, the stand-in for a mid-range phone, and checks that the first chart element draws within a second of navigation and that, across zooms and pans of the eight linked charts, the longest requestAnimationFrame interval, best of three rounds, stays within 1.5 times the recorded baseline in `app/perf-baseline.json`. Headless Chromium has no GPU, so this guards against regressions and is not a measurement on a phone. Each zoom or pan currently stalls the main thread for about 700 ms under the slowdown. The displayed placement bound is qualified by the theorem's `NormalRange` hypotheses.

## Real data pipeline

Three separate steps, none of them part of `lake build`. `scripts/fetch.mjs` (Node, no packages) sends one EarthScope dataselect request per station, channel and day and one USGS catalogue query, writing miniSEED under `<data>/mseed/<id>/<day>.mseed` and CSV under `<data>/catalogue`; days already on disk are skipped, so an interrupted fetch resumes, and a day the service has no data for is recorded as an empty `.empty` file so it is not asked for again. Concurrency is two, with exponential backoff. `scripts/selection.json` pins the stations, the one-station one-week default slice and the quarter of four stations. `Inkproof.Demo.MiniSeed` is a native module that does not import Lasm: it decodes miniSEED 2 records with Steim1 or Steim2 data in either byte order. It is tested against a real excerpt in `test/fixtures` (each record's last sample must equal the frame's reverse integration constant) and against a synthetic Steim1 record.

`Inkproof.Demo.Loaded` is a native module that does not import Lasm: `decodeTile` reads a fetched tile file into extents (`decodeTile_eq`). `Inkproof.Demo.Raw` is the same for the raw day files: `pieces` lists the byte ranges of the day files that hold a sample range (`mem_pieces`, `piece_spec`, `piece_covers`; a sample in no file is a gap) and `decodeLeaves` reads a range's bytes into one extent per sample. The browser app gives these to Web's `queryColumnsFrom`, which reads the tiles for columns of at least 2^firstLevel samples and the raw files by byte range for narrower ones, so a chart draws from `tiles/s<station>/l<level>/t<n>.bin` and `tiles/s<station>/raw/d<day>.bin` and not from a pyramid built in the page.

`Inkproof.Demo.Manifest` is a native module that does not import Lasm: `parse` reads the site's `manifest.json` (written by `toJson`, from `build-manifest` or `build-tiles`), and `top` and `samples` give a station's coarsest level and the samples its tiles cover; it also says which raw day files each station has, how many samples a file holds and the number of the first. The browser app fetches `tiles/manifest.json` before drawing and takes the number of stations, the length of the recording and each station's top level from it, so it charts whatever tile set it is served; the catalogue overlay is still the synthetic one.

`Inkproof.Demo.Catalogue` is a native module that does not import Lasm. `parseCsv` reads a USGS catalogue's `time` and `mag` columns into quakes whose time is a sample index on the grid of an `Origin` (the year, day and rate of a tile set's sample 0, written by `build-real-tiles` as `recording.json`) and whose magnitude is in tenths; a row that is malformed or lies before the recording is dropped. `build-catalogue` writes the quakes as `catalogue.json`, which the browser app fetches once and draws with `Plot.quakes`. A catalogue that fails to load is logged at warn and labelled on the chart, never drawn as a year with no earthquakes. Rows after the recording's end are kept; `Plot.quakes` shows only those in view.

## Scale and the quarter test

`Stack.peak` is the largest magnitude among a track's columns (`le_peak`), and `Plot.traces` takes one such top for each station, so a track shows its own traces whatever the recording's amplitude. Real counts reach 32767 after scaling into 16 bits, and a fixed top left the trace far outside its track. `app/quarter.test.mjs` runs the built app against the real tile set named by `INKPROOF_SITE` and is skipped without it; it also fails on any warning logged while drawing, so a missing tile cannot pass as an outage or an empty chart.

## Input robot

`Inkproof.Demo.Robot` is a native module that does not import Lasm: `run` applies random actions (wheel, pinch, drag, keys, boxes, sets, resets, link toggles) to linked charts and reports the first broken property (a zoom limit, linked charts disagreeing on x, the cursor moving under a zoom, a chart that was not addressed changing). `lake test` runs 100 seeds natively; the browser app has a button that runs 20 seeds, one per message so the page stays responsive, and `app/browser.test.mjs` checks that it reports no violation.

## Chart sources

`Inkproof.Demo.Source` is a native module that does not import Lasm. Each chart in `app/App.lean` sits between a `-- chart: <name>` line and a `-- end chart` line; `regions` reads those lines (`regions_mem`: every line shown is a line of the file) and `lake exe build-sources` writes them as `chart-sources.json` beside the tiles, which the app fetches and shows under each chart, so the text shown is the text compiled. `lake test` fails if a chart's source passes 20 lines, not counting blanks. A chart takes its tile loading and failure labelling as arguments (`stackItems`), so its source shows only how the libraries are put together.
